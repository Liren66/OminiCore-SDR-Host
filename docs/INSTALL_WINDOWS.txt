OmniCore Host (OCH) 0.4.5 — Windows 安装与驱动说明

适用范围
  Windows 10 / Windows 11，原生 x64。当前发行包不支持 ARM64 或 32 位 Windows。
  USB 数据设备：OmniCoreSDR，VID 1A86 / PID 5537。
  驱动：libusbK 3.1.0.0。安装包完全离线，包含用户态 DLL、内核驱动、安装工具和许可证。
  发行内容为 OCH 运行程序、C/C++ 接口、示例、使用文档与 USB2 实测附录；不包含 PS SDK、板端固件或完整测试工程。
  安装器不会编译或烧写 Zynq、FPGA、CH32。

首次安装
  1. 关闭其他访问 SDR 的软件，运行 OmniCoreHost-0.4.5-win64-setup.exe。
  2. 接受 Windows 正常的管理员 UAC 提示。保留“Install/check libusbK”选项。
  3. 安装完成后打开一个新的终端，运行：
       och find
       och info
       och help
  终端中的输出按标题和分组分层显示，带颜色与实时进度；重定向时自动改为纯文本。
  不需要颜色时使用 --no-color 或设置 NO_COLOR。脚本请使用 --json，结果结构保持兼容。
  安装时未连接 SDR 也可以完成软件安装。随后连接 USB 数据口（推荐 USB 3.x）并运行：
       och-driver install

驱动助手
  och-driver check        只查询目标 SDR 的驱动，不修改系统。
  och-driver install      自动安装 libusbK；已有 libusbK 时不重复替换。
  och-driver extract DIR  仅解包供检查；不生成/信任证书，不安装驱动。
                         DIR 必须不存在，提取的 INF 故意保持未签名。

安装行为
  驱动助手仅选择 VID 1A86 / PID 5537 的非复合 USB 设备；不修改 WCH-Link、
  串口、键盘、USB Hub 或其他 VID/PID。若有多个相同 SDR，同一驱动适用于这些设备。
  驱动助手用 libwdi 的正常流程为此设备生成 INF 和一次性签名目录，将该设备生成的
  签名证书加入 Windows 证书存储，再让 Windows 安装。
  内核 libusbK.sys 保持官方原文件，安装前检查固定 SHA256 和 Windows Authenticode。
  不开启测试签名，不关闭 Secure Boot、签名强制或内存完整性。
  若系统安全策略拒绝驱动，助手会报告失败；不会自动降低系统安全设置。

错误与日志
  驱动安装日志：C:\ProgramData\OmniCoreHost-driver{GUID}\install.log
  Windows 安装细节：C:\Windows\INF\setupapi.dev.log
  setup.exe 支持 /LOG="完整日志路径"；软件安装成功而驱动失败时，安装器退出码为 104。
  驱动助手退出码：0 成功/已经可用；2 设备未连接；3 需要 libusbK；4 错误；5 UAC 取消。
  未连接设备的退出码 2 不会使软件安装失败；以后运行 och-driver install 即可。

更新和卸载
  直接运行新版 setup.exe 可更新软件。请先停止数据收发并退出占用 DLL 的程序。
  卸载只移除 OmniCore Host 软件和该安装目录的 PATH 项，不移除共享 libusbK 驱动、
  驱动证书或系统 DriverStore 包，避免影响其他使用相同驱动的设备。
  用户采集文件放在自己的工作目录，安装器不会自动创建或删除这些采集数据。

依赖与来源
  licenses\ 中包含 libusbK、libwdi、GNU/MinGW 运行时许可证、来源 URL 和下载 SHA256。
  licenses\sources\ 保留对应上游源代码归档；licenses\driver-build\ 保留助手源代码与构建脚本。
  本软件和安装器尚未使用发布者代码签名证书签署；Windows 可能显示未知发布者提示。
  内核驱动的签名与上述应用程序代码签名是两件不同的事。

验证范围
  已验证驱动助手编译、目标设备枚举、已有 libusbK 时幂等跳过、离线提取、INF 精确匹配、
  内核文件哈希/签名，以及安装包内容。当前电脑原有 libusbK 保持不变。
  未在全新 Windows 虚拟机/实体机上实际执行首次驱动安装；该项仍需独立安装验收。
  若全新系统缺少签名验证所需的可信根，离线签名检查可能拒绝安装，应按 Windows 正常更新
  与组织管理策略处理；本安装器不下载/导入外部 CA 根来绕过此验证。
